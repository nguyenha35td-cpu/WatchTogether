## 2026-03-15 修复 MKV 字幕探测和提取功能

### 问题
上传 MKV 文件后无法看到字幕选项。

1. **ffprobe npm 静态包版本在处理 HTTPS URL 时 core dump**：`@ffprobe-installer/linux-x64/ffprobe`（静态编译版本 N-66595）对 HTTPS URL 会 segfault，导致字幕探测始终返回空数组。而系统 apt-get 安装的 `/usr/bin/ffprobe` (5.1.8) 正常工作。
2. **ffmpeg 字幕提取超时**：原先用 `execFile` 同步等待提取完成，大文件（1.5GB MKV）的远程提取需要较长时间，HTTP 请求超时。另外 `.vtt.tmp` 扩展名不被 ffmpeg 识别需要 `-f webvtt` 显式指定。

2. `server/index.js` ffprobe 探测：增加 `-analyzeduration 10M -probesize 10M` 参数，超时从 30s 增至 60s
3. `server/index.js` 字幕提取重写为**异步 spawn + 轮询模式**：
   - `extractSubtitleToVTTAsync()` 使用 `spawn` 非阻塞启动 ffmpeg
   - 写入 `.vtt.tmp` 临时文件，完成后 rename 为 `.vtt`（原子操作）

4. `app/page.tsx` 前端 `extractSubtitleVTT()` 改为轮询模式：每 2 秒检查一次，最多 90 次（~3 分钟）

## 2026-03-15 字幕提取性能优化：ffmpeg → 纯 JS MKV Range 解析

### 问题
字幕提取需要 3 分钟（ffmpeg 从 CDN 下载整个 655MB MKV 文件再提取几十 KB 字幕），用户反馈夸克网盘 1 秒就能提取。

### 根因
ffmpeg 提取字幕时必须从头扫描整个 MKV 文件，即使字幕数据只有几十 KB。MKV（Matroska）是交错存储的容器格式，字幕 Block 散布在各个 Cluster 中。

### 解决方案
**完全去除 ffmpeg 依赖**，改用纯 JavaScript 解析 MKV (EBML/Matroska) 容器格式 + HTTP Range 请求：

1. **`server/mkv-subtitle-extractor.js`**（全新文件）：
   - EBML 变长整数（VINT）解析器
   - Matroska 元素 ID/Size 解析
   - SeekHead → 快速定位 Tracks/Cues 元素位置
   - Tracks 解析 → 发现字幕轨（TrackNumber, CodecID, Language, Name, CodecPrivate）
   - Cues 解析 → 获取 Cluster 位置索引
   - Cluster/Block 解析 → 提取指定 Track 的字幕 Block 数据
   - ASS/SSA 标签剥离 + SRT 解析 + WebVTT 生成
   - HTTP Range 请求：只下载 MKV 头部（~512KB）+ 字幕数据块，总共 <1MB

2. **`server/index.js`**（重写字幕 API）：
   - 移除所有 ffmpeg/ffprobe 相关代码（execFile, spawn, whichBinary 等）
   - `GET /api/subtitles/vod/:fileId`：用 `probeMKVSubtitles()` 替代 ffprobe，探测+预提取
   - `GET /api/subtitles/vod/:fileId/:streamIndex`：同步返回结果，不再需要轮询
   - `probeCache` Map 缓存探测结果避免重复解析
   - `extractionInProgress` Map 追踪进行中的提取 Promise

3. **`app/page.tsx`**（前端简化）：
   - `extractSubtitleVTT()` 移除轮询逻辑，直接 await 单次请求
   - 后端同步返回 `{status:"ready", url:...}` 或错误

4. **`server/Dockerfile`**：移除 `apt-get install ffmpeg`
5. **`server/package.json`**：移除 `@ffmpeg-installer/ffmpeg` 和 `@ffprobe-installer/ffprobe`

### 预期性能
- 探测字幕轨：<2 秒（之前 ffprobe 需要 5-10 秒）
- 提取单条字幕：<5 秒（之前 ffmpeg 需要 1-3 分钟）
- 网络传输量：<1MB（之前需下载整个 655MB 文件）

### 部署
- 后端镜像: `watchtogether-server:fast-subtitle`
- 前端镜像: `watchtogether-frontend:fast-subtitle`
- Docker 参数不变: `-v subtitle-cache:/app/subtitles`

## 2026-03-15 修复字幕缺失：两轮提取策略

### 问题
4 个视频的字幕有约 7-10% 缺失（例如 312/337），观看时部分台词没有字幕显示。

### 根因
`MAX_CLUSTER_READ = 768KB` 限制了每个 Cluster 的读取大小。MKV Cluster 中字幕 Block 排在视频/音频 Block 之后，如果视频帧数据大于 768KB，字幕就被截断了。

### 解决方案（`server/mkv-subtitle-extractor.js`）
**两轮提取策略（Two-Pass）**：

1. **Pass 1**（快速扫描）：768KB cap，10 路并发读取所有 233 个 Cluster，~1 秒完成
2. **Pass 2**（补全）：对 `actualSize > 768KB` 的截断 Cluster（约 70-100 个），用**完整 Cluster 大小**重新读取
3. 用 `clusterBlocksMap` 存储每个 Cluster 的字幕 blocks，Pass 2 的结果**替换**（不是追加）Pass 1 的结果，避免遗漏
4. 新增 `parseClusterBuffer()` 辅助函数，可处理 unknown size (-1) 的 Cluster

## 2026-03-16 VOD 文件自动清理（省存储费）

### 背景
腾讯云 VOD 存储按日峰值计费，用户看完视频后不再需要，但视频一直存在 VOD 中持续产生存储费用。

### 实现（`server/index.js`）

1. **`deleteVodFile(fileId)`**：调用腾讯云 `DeleteMedia` API 删除 VOD 文件，同时清理本地字幕缓存和 probeCache
2. **`cleanupSubtitleCache(fileId)`**：删除 `subtitles/vod_{fileId}_*.vtt` 缓存文件
3. **`cleanupRoomVodFiles(roomId, playlist)`**：收集房间播放列表中所有 vodFileId，并行调用 deleteVodFile
4. **房间销毁时自动清理**：`handleLeaveRoom()` 中 `room.participants.size === 0` 时调用 cleanupRoomVodFiles
5. **单个视频删除时清理**：`playlist_remove` 事件中找到被删除视频的 vodFileId 并调用 deleteVodFile
6. **vodFileTracker**：`playlist_add` 时注册 fileId 和上传时间到 Map 中
7. **24 小时兜底定时清理**：`startVodCleanupTimer()` 每 30 分钟扫描 vodFileTracker，删除超过 24 小时的文件（防止服务器重启丢失房间内存导致 VOD 文件成为孤儿）

### 部署
- 后端镜像: `watchtogether-server:vod-cleanup`
- 服务器: 101.34.83.116, 实例 lhins-bjtqlnjc
