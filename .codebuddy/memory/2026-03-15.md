## 2026-03-15 修复 WebSocket 连接和 API 跨端口问题

### 问题
创建房间时一直显示"连接中..."，无法建立 WebSocket 连接。

### 根因
1. `NEXT_PUBLIC_WS_URL` 是 Next.js 构建时变量，Docker 运行时设置无效
2. fallback 逻辑用 `window.location.host`（80 端口），WebSocket 连到了前端 80 而非后端 3001
3. API fetch 用相对路径 `/api/...` 也打到前端 80 端口，且 rewrites 在 Docker standalone 模式下不可靠

### 修复
- `hooks/use-websocket.ts`: WS URL 改为 `hostname:3001`（不依赖构建时环境变量）
- `app/page.tsx`: 新增 `getApiBase()` 返回 `${protocol}//${hostname}:3001`，所有 fetch 用绝对地址
- `next.config.mjs`: 移除无效 rewrites

### 部署
- 前端镜像: `watchtogether-frontend:vod-fix`
- `docker run -d --name watchtogether-frontend --restart unless-stopped -p 80:3000 -e HOSTNAME=0.0.0.0 watchtogether-frontend:vod-fix`
