## 2026-03-16 字幕提取改造：纯 JS EBML → ffmpeg

### 背景
纯 JS MKV Range 解析提取字幕（Two-Pass 策略）下载量过大（~270MB），请求数多（100~300+），虽然比最初 ffmpeg 全文件扫描快，但仍有优化空间。

### 改造内容
将字幕**提取**从纯 JS EBML 解析改回 ffmpeg（但方式完全不同于最初版本）：
- ffmpeg 直接读取远程 VOD URL，只 demux 字幕轨，不下载整个文件
- 命令: `ffmpeg -y -i <VOD_URL> -map 0:s:<streamIndex> -c:s webvtt <output>.vtt`
- 字幕**探测**（probe）保持不变：纯 JS MKV Range 解析，只读 ~512KB 头部

### 修改文件
1. **`server/index.js`**:
   - 添加 `const { execFile } = require("child_process")`
   - 新增 `extractSubtitleWithFFmpeg(mediaUrl, streamIndex, vttPath)` 函数
   - `GET /api/subtitles/vod/:fileId/:streamIndex` 改用 ffmpeg 提取，不再依赖 `extractMKVSubtitle`
   - 只导入 `probeMKVSubtitles`，不再导入 `extractMKVSubtitle`

2. **`server/mkv-subtitle-extractor.js`**:
   - 从 1273 行精简到 ~370 行
   - 只保留 probe 相关代码：EBML 解析器、SeekHead/Tracks 解析、HTTP Range fetcher
   - 删除：Cluster/Block 解析、ASS/SRT/VTT 转换、Two-Pass 提取逻辑、sequential scan fallback
   - 只导出 `probeMKVSubtitles` 和 `codecIdToShortName`

3. **`server/Dockerfile`**: 添加 `apt-get install ffmpeg`
4. **`server/nixpacks.toml`**: 添加 `aptPkgs = ["ffmpeg"]`

### 预期性能改善
| 指标 | 旧方案（EBML Range） | 新方案（ffmpeg） |
|---|---|---|
| 下载量 | ~270MB | <5MB |
| HTTP 请求数 | 100~300+ | <10 |
| 代码量 | ~1100 行 | ~30 行 |
| 耗时 | 5~15 秒 | 1~5 秒 |

## 2026-03-20 回退字幕提取方案：ffmpeg → 纯 JS Two-Pass

## 2026-03-20 Two-Pass 字幕提取性能优化

### 问题
回退到 Two-Pass 方案后实测仍然慢：总耗时 **74 秒**（Pass 1: 8s/173MB, Pass 2: 66s/612MB）。
根因：Pass 2 对所有 176 个 truncated clusters 全量重读（612.5MB），但实际只多恢复了 49 个字幕 block。
大部分 truncated cluster 在 Pass 1 的 768KB 范围内已经找到了字幕。

### 优化内容（`server/mkv-subtitle-extractor.js`）
1. **Pass 2 条件优化**：只对 Pass 1 中**没找到任何字幕 block** 的 truncated cluster 做全量重读。
   之前条件：`actualSize > 768KB`（176 个 cluster → 612.5MB）
   现在条件：`actualSize > 768KB && blocks.length === 0`（预计 ~30-50 个 cluster → ~100-170MB）
2. **并行度提升**：Pass 1/Pass 2 从 10 并发提高到 16 并发
3. **maxSockets 提升**：HTTP Agent maxSockets 从 16 提高到 32

### 预期效果
- Pass 2 数据量从 612MB → ~100-170MB
- 总耗时从 74秒 → ~15-25秒
- 字幕完整度仍为 100%

### 部署
- 后端镜像: `watchtogether-server:pass2-opt2`
- 服务器: 101.34.83.116, 实例 lhins-bjtqlnjc

## 2026-03-20 精确模式（Precision Mode）最终验证成功 🎉

### 核心发现
MKV Cues 中的 **CueRelativePosition (0xF0)** 字段可精确定位字幕 block 在 cluster 中的偏移，无需下载整个 cluster。

### 实现要点
- 解析 Cues 获取每个字幕 block 的 CueRelativePosition
- 计算绝对文件偏移 = cluster_offset + cluster_header_size - relative_position
- 每个字幕 block 只读 4KB，32 并发下载
- 先读 cluster header（32字节）获取 Cluster Timestamp

### 验证结果（687MB MKV 文件，359 条字幕）

| 版本 | 耗时 | 下载量 | 字幕完整性 |
|------|------|--------|-----------|
| 原始 Two-Pass | 74s | 786MB | 359 ✅ |
| 大块下载 | 54s | 653MB | 359 ✅ |
| **精确模式** | **2.77s** | **1.41MB** | **359 ✅** |

性能提升 **~26 倍**，下载量减少 **~460 倍**，字幕 100% 完整。

- 后端镜像: `watchtogether-server:precision`
- 服务器: 101.34.83.116, 实例 lhins-bjtqlnjc
- Docker: `docker run -d --name watchtogether-server --restart unless-stopped -p 3001:3001 --env-file .env -e VOD_REGION=ap-chongqing -v subtitle-cache:/app/subtitles watchtogether-server:precision`
